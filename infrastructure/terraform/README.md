# Civic Intelligence Platform — Terraform

Cloud infrastructure for the platform. Provider-agnostic where reasonable;
defaults to AWS. Storage module supports Cloudflare R2 as an alternative to S3.

## Structure

```
terraform/
├── main.tf              # top-level: composes all modules into one stack
├── variables.tf         # global variables (overridable per env via tfvars)
├── versions.tf          # provider versions + backend config
├── modules/
│   ├── vpc/             # VPC + subnets (public/private/db) + NAT GWs + flow logs
│   ├── rds/             # Postgres 16 + pgvector, custom parameter group
│   ├── s3/              # S3 (or Cloudflare R2) buckets
│   ├── redis/           # ElastiCache Redis cluster (TLS + at-rest encryption)
│   ├── nats/            # IRSA + log group for NATS JetStream on EKS
│   ├── eks/             # EKS cluster + managed node group + IRSA + ALB role
│   └── dns/             # Cloudflare DNS records
└── environments/
    ├── dev/
    ├── staging/
    └── prod/
```

## Modules at a glance

| Module    | Provider       | What it creates                                                            |
| --------- | -------------- | ------------------------------------------------------------------------- |
| vpc       | aws            | VPC, 3 AZs of public/private/db subnets, NAT GWs, flow logs.              |
| rds       | aws            | Postgres 16 instance with pgvector preload, KMS, SSM-stored password.      |
| s3        | aws / cloudflare | Buckets for raw-documents, exports, evidence, terraform-state.         |
| redis     | aws            | ElastiCache Redis 7 cluster with TLS + at-rest encryption.                 |
| nats      | aws            | IRSA role + CloudWatch log group for NATS JetStream (runs on EKS via Helm). |
| eks       | aws            | EKS cluster, managed node group, IRSA OIDC, ALB controller role.          |
| dns       | cloudflare     | Apex + subdomain CNAMEs → EKS ALB, SPF TXT, MX for SES inbound.          |

## Usage

```bash
# Per-env init (state backend differs per env to isolate prod from staging)
cd infrastructure/terraform
terraform init -backend-config=environments/prod/backend.hcl

# Plan
terraform plan -var-file=environments/prod/terraform.tfvars

# Apply
terraform apply -var-file=environments/prod/terraform.tfvars
```

## R2 alternative for storage

To use Cloudflare R2 instead of AWS S3:

```hcl
# environments/prod/terraform.tfvars
storage_backend = "r2"
r2_account_id   = "<your-cloudflare-account-id>"
```

Application code reads `S3_ENDPOINT` (set in the Helm ConfigMap) and the R2
buckets are addressable via the standard S3 API.

## State management

State is stored in S3 with locking via DynamoDB (or the new S3-native lock
file when `use_lockfile=true`). Per-environment backend config files:

```
environments/dev/backend.hcl
environments/staging/backend.hcl
environments/prod/backend.hcl
```

## Secrets

* RDS master password: generated by `random_password`, stored in SSM
  Parameter Store (SecureString) at `/civic/<env>/database/password`.
* Redis AUTH token: stored at `/civic/<env>/redis/auth_token`.
* The Helm chart reads these via `ExternalSecret` resources (when
  `externalSecrets.enabled=true`).

## Cost & guardrails

* `rds_deletion_protection=true` in prod.
* `prevent_destroy` lifecycle on S3 buckets in prod.
* All storage is KMS-encrypted.
* RDS uses `gp3` storage + `performance_insights_enabled=true`.
* `rds.logical_replication=1` enables CDC for the search projection
  reindexer.

## Known limitations / future work

* EKS ALB DNS is currently a placeholder — in production it should be
  populated from `kubectl get ingress` after the AWS Load Balancer
  controller reconciles the Ingress object. Consider an `external`
  data source or a `kubernetes_ingress_v1` data source.
* NATS JetStream is deployed via Helm into the EKS cluster, not via
  Terraform-managed EC2. A dedicated instance may make sense at very
  high throughput.
